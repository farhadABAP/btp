🚀 C_ABAPD CDS Master Plan (Eclipse ADT)

🎯 Phase 1: The Basics (Data & Filters)

Goal: Understand how to build a view and push filtering logic to the database.

1. Create a CDS View with a Filter: Modify your existing ZI_TRIAL_ORDERS to only show orders where amount > 100.
   · Exam focus: Code pushdown. Filtering in CDS is faster than filtering in ABAP.
   · Code snippet: define view ZI_TRIAL_ORDERS as select from ztrial_orders { key order_id, amount } where amount > 100;

🔗 Phase 2: Associations (High Exam Frequency)

Goal: Learn how to link two tables without writing explicit JOINs.

1. Create a Customer Table: Create ZTRIAL_CUSTOMERS (Fields: client, customer_id, customer_name, country).
2. Insert Data: Write a quick class to add 2 customers (e.g., ID 1 = Alice, ID 2 = Bob).
3. Link them: Modify your ZTRIAL_ORDERS table to include a customer_id field.
4. Create the Association: In your CDS view, use association [0..1] to ZI_TRIAL_CUSTOMERS as _Customer on $projection.customer_id = _Customer.customer_id.

🛡️ Phase 3: Access Control (DCL)

Goal: Restrict data based on user roles (Row-level security).

1. Create a DCL Object: Right-click package -> New -> Core Data Services -> Access Control.
2. Name: ZAC_TRIAL_ORDERS
3. Bind to View: In your CDS view, change @AccessControl.authorizationCheck: #NOT_REQUIRED to #CHECK.
4. Define the Rule: Use grant select on ZI_TRIAL_ORDERS where ( customer_name ) = aspect pfcg_auth( ... ); (We will code the exact syntax tomorrow).

🧮 Phase 4: Calculations & Aggregations

Goal: Transform data in the database layer.

1. Calculated Fields: Add a field in your view that multiplies amount * 1.19 to calculate tax.
2. Aggregation: Create a new view ZI_ORDER_SUMMARY that calculates the SUM(amount) and groups by customer_id.
   · Exam focus: Replacing ABAP COLLECT or LOOP with database-level aggregations.

🧠 Phase 5: Exam Scenarios to Practice

· Scenario A (Pushdown): Convert a traditional SELECT * followed by LOOP ... WHERE amount > 1000 into a CDS view.
· Scenario B (Annotations): Add @UI.lineItem: [{ position: 10 }] to fields to prepare them for a Fiori UI.
· Scenario C (Associations): Use \_Customer-Country to fetch the customer's country directly in the Orders view without a JOIN.
